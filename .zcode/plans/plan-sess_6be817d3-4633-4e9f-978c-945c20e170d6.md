# Fix email-service failures: broken rate-limit Redis store + Scaleway TEM SMTP wiring

## Diagnosis (two separate problems)

**1. `RedisStore incr error` (your pasted stack trace) — rate limiting is silently dead.**
`CustomRedisStore` (`backend/middlewear/rateLimiter.js`) snapshots `redisService.client` in its constructor, which runs during the synchronous `require()` chain — before `RedisService.initialize()` creates the client. Every store instance captured `null`; every limiter call throws, logs your trace, and returns 1, so no limiter has ever counted anything. It surfaces at email endpoints because those mount the limiters (`authRoute.js`).

**2. Email never sends — SMTP endpoint misconfigured.**
Boot log: `getaddrinfo ENOTFOUND smtp.scaleway.com` → `isConfigured=false` → all sends no-op; register replies `emailSent: false` with "bypass verification". Per Scaleway's docs, TEM's SMTP endpoint is `smtp.tem.scaleway.com` (port 587 STARTTLS), **username = the Project ID where the TEM domain was created**, **password = the secret key of an API key** permitted for TEM SMTP sending.

## Changes

1. **`backend/middlewear/rateLimiter.js`** — lazy client getter instead of the constructor snapshot:
   ```js
   constructor(options = {}) {
     this.prefix = options.prefix || 'ratelimit:';
   }
   // Resolve the shared client lazily: RedisService connects after this module
   // is required, so snapshotting it in the constructor captures null.
   get client() { return redisService.client; }
   ```

2. **`.env` (root — the file `npm start` loads)** — via targeted `sed` only; the file is never read or printed, so secrets never enter this session:
   - `SMTP_HOST` → `smtp.tem.scaleway.com`
   - `SMTP_PORT` → `587`, `SMTP_SECURE` → `false` (STARTTLS; `true` is only for 465)
   - `SMTP_USER` ← value of `SCW_DEFAULT_PROJECT_ID` (the Project ID behind the `jp-tutor.eu` TEM domain)
   - `SMTP_PASS` ← value of `SCW_SECRET_KEY`
   - `EMAIL_FROM` → an address on your validated domain, e.g. `Japanese AI Tutor <noreply@jp-tutor.eu>`
   - If the `SCW_*` values aren't in `.env`, I'll insert clearly marked placeholders and you paste the two values in yourself (never into chat).

3. **Caveat to verify at test time:** the API key must have the TEM SMTP-sending IAM permission (Scaleway's "Generate API keys for API and SMTP sending" procedure). If `transporter.verify()` fails with an SMTP **535 auth** error, that permission/credential is the remaining fix — yours to do in the Scaleway console.

2. `POST /api/auth/login` with dummy creds a few times → `ratelimit:login:*` keys appear in Redis with TTLs (`docker exec ai-tutor-redis redis-cli keys 'ratelimit:*'`) — proving the store counts now.
3. Optionally register a test account → server replies `emailSent: true`; the verification link points at `jp-tutor.eu`.
